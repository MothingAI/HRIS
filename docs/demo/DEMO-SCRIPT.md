## 准备（演示前 5 分钟，二选一，互斥）

```bash
# 路径 A（空白全流程）：只清工具在途单，确保一个可登录/试用中/无在途的专属身份，
# 收尾会打印演示账号 demoNN@example.com —— 演示完整走第 2 步（新建草稿→编辑→提交）
python scripts/prep_demo.py --blank

# 路径 B（预填待办，幂等）：确保一条工具身份的 PENDING 待办 —— 演示【跳过第 2 步】，
# 直接从第 3 步主管审批开始；上一轮批/驳完会自动顺延下一个编号，历史全保留
python scripts/prep_demo.py
```

- 两条路径**不要都跑**：路径 A 后已建好的草稿/提交会被路径 B 视为"已有待办"
  而跳过；同一路径连跑（含演示批完后重跑 B）是幂等安全的。
- 演示身份是**工具自有**的 `DEMO-NN`（员工「演示员工NN」+ 账号
  `demoNN@example.com`，密码同 `.env` 的 `DEMO_PASSWORD`）。所有权由工具清单
  （`prepDemoRegistry`，仅 root 可访问）登记的实际创建记录决定，可编辑的工号/
  邮箱字段不作凭据——普通员工即使被改成 DEMO-NN 前缀也不会被接管或清理
  （REV-010 第二轮）。
- 记下脚本收尾打印的**实时统计**与**演示账号**，第 1/4 步口播直接引用这些
  数字——**不要用写死的旧数字**。
- 开相互独立的浏览器上下文：HR、演示员工（准备输出的 demoNN）、主管 A
  （另备主管 B、员工 A 两个用于第 5 步，可后开）。

## 六步演示（约 4 分钟）

1. **HR 主数据**（HR 上下文，`hr@example.com`，约 40s）
   员工管理：员工列表与彩色状态标签；演示按部门/状态筛选、行内编辑入口。
   口播：员工/部门主数据与账号绑定全在这维护；一个账号至多绑一名员工（数据库
   唯一约束兜底，平台模型持续维护）。

2. **员工编辑和提交**（演示员工上下文，`demoNN@example.com`，约 50s；**仅路径 A**）
   我的转正 → 新建转正申请 → 填写自评/试用期收获 → **保存草稿** → 草稿表出现行
   （只有"编辑草稿/提交"）→ **编辑**改两句再保存（同一草稿更新，不新建）→
   **提交** → 状态 PENDING，按钮变只读"查看详情与轨迹"。
   口播：草稿可反复编辑；提交后本人不能再改，防篡改从状态机开始。
   路径 B（预填待办）**跳过本步**——该员工已有 PENDING 待办，再新建提交会被
   服务端 409 拒绝（防重复保护），直接进入第 3 步。

3. **主管审批**（主管 A 上下文，`manager.a@example.com` 王建国，约 40s）
   待我审批：出现「演示员工NN」的单 → 通过。（可选：先演示驳回——弹窗不填意见
   点确认，服务端 400"驳回必须填写审批意见"，填意见后才成功；说明前端校验可绕、
   服务端不能。）
   口播：审批是服务端受控动作：事务里校验操作者=该员工当前直属主管 + 行锁，
   并发双击只会成一个。

4. **HR 状态/统计**（HR 上下文，约 40s）
   人事概览：在职**不变**、**试用 -1**、**待审批 减 1**——注意不是固定的
   "1→0"：准备阶段统计里可能还有其他员工的待办（如主实例保留的历史演示单），
   口播用"待审批 N-1，N=准备时打印的实数"（差值口径与 `verify_reports.py`
   的相对断言一致）；部门表人数不变；回员工管理看「演示员工NN」状态
   "试用中"→"正式"。
   口播：统计由服务端按角色数据范围聚合，口径与验证脚本同源（13/13 相对断言）。

5. **越权隔离**（员工 A / 主管 B 上下文，约 40s）
   员工 A（`employee.a@example.com`）我的档案：只见本人 1 行；主管 B
   （`manager.b@example.com`）待我审批：**空**（看不到主管 A 组的单）；两者菜单
   都没有「人事概览」。
   口播：菜单只是第一层；拿员工/主管 token 直接调统计 API 也只能数到本人 1 /
   本组（主管自己的范围数），拿不到全公司——四层防线（菜单/动作白名单/数据
   范围/服务端校验）。

6. **低代码增字段**（HR 上下文，约 40s）
   员工管理 → 打开一名旧记录（如 E005）编辑 → 表单底部已有"紧急联系人"输入框
   （管理员此前用平台配置加的字段，**未改任何源码**）→ 填值 → 提交 → 重开回显。
   口播：加字段走官方 API 等价于设计器拖拽；旧记录值为空也能正常打开；员工侧
   我的档案同步出新列（证据 `n3-lowcode-6-employee-view.png`）。

## 失败备用

- 账号登录失败：核对 `.env` `DEMO_PASSWORD`；`seed.ps1 -WithDemo` 幂等重跑。
- 提交 409：不是故障——这是防重复保护（该员工已有在途 PENDING）。两条出路：
  ① 换成路径 B 话术（待办已在，直接演示第 3 步主管审批）；② 想演完整第 2 步
  就先 `prep_demo.py --blank`（只会清工具在途单，不影响他人待办与历史）。
- 页面为空：确认 `seed.ps1` 已跑、插件动作已随重启生效（种子链内含重启）。
- 浏览器异常：用 `docs/evidence/` 截图与控制台输出代讲（n2-*/n3-*/n4-*）。
