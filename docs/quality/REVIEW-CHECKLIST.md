# HRIS 低代码交付审查标准

审查负责人：Codex。实施证据提供方：Claude Code。

审查时先阅读 BLACKBOARD 和实际文件；没有 Git 仓库时直接检查文件，不能因缺少提交号停止审查。平台配置如未导出到仓库，需检查真实实例或可恢复配置，不能只凭截图推断后端正确。

## 1. 分级与结论

- P0：严重数据泄露、凭据泄露、破坏性默认操作等。
- P1：核心流程不可用、可越权读取 / 修改、可伪造审批、状态不一致、重复处理等。
- P2：一般功能不完整、恢复步骤缺失、统计口径错误、证据不足等；如阻止核心演示或导致权限泄露，按实际影响上调。
- P3：次要交互、样式或文案问题。

`ACCEPTED`：本阶段验收条件有证据支持，没有未关闭的 P0/P1。接受某阶段不自动代表全部系统验收。

`CHANGES_REQUESTED`：存在需修复问题。证据不够应明确写“未验证”，不能武断声称一定有缺陷，也不能视为通过。

## 2. S0 / S1：环境与部署

- [ ] 有实际版本清单、官方来源、免费 / 收费能力结论；关键能力有本机验证。
- [ ] 镜像固定精确版本，数据库版本受支持，插件与平台兼容。
- [ ] Docker CLI、Engine、Compose、平台就绪分别验证。
- [ ] 平台默认只绑定本机，数据库不直接暴露宿主机端口。
- [ ] 密钥不在仓库、黑板或截图，`.env.example` 不含真实值。
- [ ] 停止脚本保留卷；重启后配置和业务记录保留。
- [ ] README / RUNBOOK 给出真实可用入口和启动步骤，而非计划中的命令。

## 3. S2：数据与身份

- [ ] 使用真实原生登录，不用前端角色下拉框冒充认证。
- [ ] user 与 employee 唯一绑定，employeeNo 唯一。
- [ ] 至少两名主管和各自员工，实际账号可验证隔离。
- [ ] HR、主管、员工没有管理员配置权限。
- [ ] 主管只看直属范围，不因同部门获得额外权限。
- [ ] 详情、列表、关系展开、更新、导出、聚合都遵循服务端权限；未使用动作关闭。
- [ ] 员工不能伪造 employee、approver 或状态；HR 不能普通更新强行转正。
- [ ] 日志业务角色只读，不允许伪造、更新或删除。
- [ ] 种子数据虚构，重复执行不重复创建；初始人数与文档一致。

## 4. S3：低代码与业务闭环

- [ ] 管理员可通过配置增加选填字段，不改前端源码；新表单生效，旧记录可读。
- [ ] 平台配置的实际内容能定位或导出，不能只有口头描述。
- [ ] 草稿只能本人修改和提交；提交后内容不能被普通角色改写。
- [ ] approver 来自服务端提交时的直属主管快照；缺少主管时阻止提交并反馈。
- [ ] 只有指定主管可以审批，不能自批；直接 API 调用同样受限。
- [ ] 驳回理由必填，驳回不改变员工为 REGULAR，再申请保留历史。
- [ ] 通过同时写入申请、员工状态和审批记录，失败回滚；异步独立更新不算事务证据。
- [ ] 重复点击、并发提交、同时通过 / 驳回只产生一个合法结果。
- [ ] 默认更新、批量更新等接口无法绕过受控业务动作。
- [ ] 已转正 / 离职员工不能通过绕过入口再次提交。
- [ ] 页面显示明确中文状态、空状态和冲突 / 失败反馈。

最小动态证据：一条通过、一条驳回后再申请；员工 A 对 B 的越权详情和更新；主管 A 对 B 的越权审批；重复处理与竞争；事务回滚。记录实际返回和数据结果，不能只写测试名称。

## 5. S4：统计与可恢复交付

- [ ] 在职人数 = PROBATION + REGULAR；待转正人数和待审批数分别计算。
- [ ] 初始总人数 20、在职 18、试用 8；通过一条后在职仍 18、试用 7。
- [ ] 主管和员工不能通过计数或报表看到越权数据。
- [ ] 固定版本的配置导出 / 导入或备份 / 恢复方案真实可用。
- [ ] 在隔离的新卷实例实际重建过，记录版本、步骤和结果。
- [ ] 没有提交未脱敏数据库、会话 Token、密码或真实员工数据。
- [ ] 演示账号密码获取方式明确，账号与角色一致。
- [ ] 有 3 分钟演示脚本、实际截图、已知限制和故障说明。
- [ ] 区分平台能力、自己的业务配置与自定义扩展，不夸大自研范围。

## 6. 证据与协作

- [ ] 黑板记录的文件、命令、提交和截图实际存在，阶段状态与实际一致。
- [ ] 没有把未执行测试、未启动平台或环境受阻写成已通过。
- [ ] Claude 只标 READY_FOR_REVIEW；ACCEPTED 有 Codex 的审查记录。
- [ ] 失败项和环境限制保留，不用删测试、改口径或换管理员账号规避。
- [ ] 设计变化记录原因、影响与处理方式。

## 7. 审查条目模板

```text
ID：REV-001
级别：P1
标题：具体可观察的问题
位置：文件绝对路径与行号，或平台集合 / 角色 / 动作路径
复现：角色、前置数据、操作或请求、实际结果
影响：哪些用户与数据受影响
依据：静态实现、配置、动态请求或日志；未验证部分明确说明
修复建议：最小修复方向
验收：修复后需要成立的断言和复核步骤
状态：OPEN / 已修复待复核 / CLOSED
```

只有 P3 且不影响演示时可将其列为后续优化；不能把权限、数据或事务问题降级成样式建议。
